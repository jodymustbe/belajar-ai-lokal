## Hari ke-4: Pemahaman Context Window & KV Cache pada Proses Inference LLM

**Target:** Memahami konsep KV Cache, cara kerjanya dalam mempercepat proses *inference*, serta mengukur langsung pengaruh perubahan `num_ctx` terhadap konsumsi VRAM pada `qwen3.5:2b-q4_K_M`.

### Ringkasan Konsep
* **Gambaran Umum (Overview):** KV Cache adalah mekanisme penyimpanan sementara (*caching*) untuk vektor **Key (`K`)** dan **Value (`V`)** hasil perhitungan *attention* pada token-token sebelumnya agar dapat digunakan kembali selama proses *inference*.
  * **Keuntungan:** Mempercepat generasi teks (*decode*) secara drastis karena menghindari perhitungan ulang yang berulang.
  * **Kekurangan (Trade-off):** Memakan kapasitas memori VRAM secara signifikan, membuat kode *inference* lebih kompleks, dan **tidak dapat digunakan saat *training*** (karena bobot model terus berubah saat *training*).
* **Cara Kerja Generasi Teks (Dengan vs Tanpa KV Cache):**
  * **Tanpa KV Cache:** Setiap kali model menghasilkan 1 token baru, seluruh urutan token dari awal harus dihitung ulang dari nol (*komputasi kuadratik / lambat*).
  * **Dengan KV Cache:** Vektor `K` dan `V` token lama disimpan dan digabungkan (*concatenate*) dengan token baru:
    1. **Tahap Awal (*Prefill*):** Model memproses seluruh token *prompt* input sekaligus, lalu menyimpan vektor `K` dan `V`-nya ke dalam cache di VRAM.
    2. **Tahap Generasi (*Decode*):** Untuk setiap 1 token baru, model hanya menghitung vektor Query (`Q`), `K`, dan `V` khusus untuk token baru tersebut saja.
    3. **Penggabungan Cache:** Vektor `K` dan `V` token lama diambil langsung dari memori cache tanpa dihitung ulang, digabungkan dengan `K` dan `V` token baru, lalu digunakan untuk memprediksi token berikutnya.
* **Context Length (`num_ctx`):** Batas maksimal jumlah token (gabungan *prompt* + riwayat chat + jawaban) yang dapat ditampung dan diakses model di dalam memori sekaligus. Pada Ollama dengan GPU di bawah 24 GB VRAM, nilai default-nya adalah **4096 token**.
* **Rumus Dasar Ukuran Memori KV Cache:**
Ukuran KV Cache (Bytes) = 2 × Layers × KV_Heads × Head_Dim × Context_Length × Data_Type_Size
  * **`2`:** Mewakili dua vektor yang disimpan (**Key** dan **Value**).
  * **`KV Heads`:** Jumlah *head* khusus Key-Value (pada model modern dengan *Grouped-Query Attention / GQA* seperti Qwen, jumlahnya jauh lebih kecil daripada *attention head* utama sehingga menghemat VRAM).
  * **`Data Type Size`:** Ukuran presisi angka dalam byte (`2` byte untuk `FP16` standar, atau `1` byte jika menggunakan kuantisasi KV cache `q8_0`).

### Hasil Pengujian KV Cache & `num_ctx` (`qwen3.5:2b-q4_K_M`)

#### 1. Parameter Arsitektur Model (`/api/show`)
* **Arsitektur:** `qwen35` | **Layers:** `24` | **Embedding Length:** `2048`
* **Attention Heads (`Q`):** `8` | **KV Heads:** `2` (*rasio GQA 4:1*) | **Head Dim:** `256`

#### 2. Perbandingan Hitungan Rumus vs Pengukuran Nyata di GPU
| `num_ctx` | Teori KV Cache (`f16` / `q8_0`) | Total VRAM Ollama (`/api/ps`) | Kenaikan Nyata (`Delta`) | Total GPU Terpakai (`nvidia-smi`) | Status GPU |
| :---: | :---: | :---: | :---: | :---: | :---: |
| **2048** | 96,00 MiB / 48,00 MiB | **1.525,5 MiB** | Baseline (`+0,0 MiB`) | 2.361 MB | **100% GPU** |
| **4096** | 192,00 MiB / 96,00 MiB | **1.551,5 MiB** | **+26,0 MiB** | 2.387 MB | **100% GPU** |
| **8192** | 384,00 MiB / 192,00 MiB | **1.663,5 MiB** | **+138,0 MiB** | 2.498 MB | **100% GPU** |

#### 3. Penjelasan Sederhana dari Hasil Pengujian
1. **Semakin panjang konteks (`num_ctx`), semakin besar VRAM yang dipakai:**  
   Saat jatah ingatan percakapan diperbesar dari `2048` ke `4096` token, pemakaian VRAM naik **26 MiB**. Saat digandakan lagi ke `8192` token, kenaikannya melonjak menjadi **138 MiB** karena cache dan buffer perhitungan yang harus disiapkan GPU ikut membesar.
2. **Kenapa kenaikan VRAM nyata (`+26 MiB`) jauh lebih hemat dibanding hitungan rumus awal (`+96 MiB`)?**  
   Rumus dasar mengasumsikan seluruh **24 layer** di dalam model menyimpan KV Cache penuh. Namun, keluarga **Qwen 3.5** memakai arsitektur campuran (*hybrid attention*): hanya **6 dari 24 layer** yang memakai *attention* standar dengan KV Cache yang membesar mengikuti `num_ctx`, sedangkan **18 layer lainnya** memakai *linear attention* yang ukuran memorinya tetap dan tidak ikut membengkak saat konteks diperpanjang.
3. **Sangat aman di RTX 3050 4 GB:**  
   Bahkan pada pengaturan panjang konteks **`8192` token**, `qwen3.5:2b-q4_K_M` hanya memakai **1.663,5 MiB** di Ollama (total `2.498 MB` termasuk Windows). Artinya masih tersisa ruang aman sekitar **1.536 MiB** sebelum menyentuh batas maksimal VRAM laptop (`~3.200 MiB`), sehingga model tetap berjalan **100% di GPU** tanpa meluber (*spill*) ke RAM.

### Kesimpulan
> KV Cache menukar kapasitas memori VRAM dengan kecepatan komputasi. Berkat kombinasi ukuran model 2B terkuantisasi dan arsitektur *hybrid attention* pada `qwen3.5:2b-q4_K_M`, peningkatan `num_ctx` hingga **8192 token** hanya menambah konsumsi VRAM sebesar **138 MiB** dan tetap berjalan **100% di GPU**, memberikan ruang konteks yang sangat lega untuk membangun *harness* dan *tool calling* di fase berikutnya.
