## Hari ke-8: Mini-Proyek Kalkulator Kelayakan VRAM & Validasi Akurasi (`model_fit_calc.py`)

**Target:** Membangun kalkulator CLI berbasis Python (`01-fundamental/model_fit_calc.py`) untuk memprediksi kebutuhan VRAM dan status kelayakan *100% GPU offload* dari metadata GGUF/Ollama, serta memvalidasi akurasinya terhadap 3 model berbeda.

### Konfigurasi Lingkungan & Formula Estimasi
- **Target Hardware:** NVIDIA GeForce RTX 3050 Laptop GPU (`4.096 MiB` Total VRAM, reservasi OS `1.200 MiB`, kapasitas pakai `2.896 MiB`)
- **Parameter Pengujian:** `num_ctx = 4096`, `KV Cache = q8_0` (`OLLAMA_FLASH_ATTENTION = 1`, `OLLAMA_KV_CACHE_TYPE = q8_0`)
- **Formula Total VRAM:** `VRAM_est = Bobot_GGUF + KV_Cache + Overhead_Runtime`
- **Formula KV Cache:** `KV_Cache (bytes) = 2 * L_kv * H_kv * D_head * num_ctx * B_kv` (khusus arsitektur *hybrid* `qwen35`, hanya `1/4` layer aktif menyimpan KV cache penuh ditambah *recurrent buffer* `~16 MiB`)
- **Formula Overhead Runtime:** `Overhead_Runtime (MiB) = 240 + (0,04 * Bobot_GGUF) + ((num_ctx / 1024) * 10)`

### Rincian Analisis & Temuan Validasi
- **Rincian `qwen3.5:2b-q4_K_M` (`1,882 B`, `5,37 bits/weight`):** Membutuhkan Bobot GGUF `1.215,4 MiB` + KV Cache `41,5 MiB` + Overhead `328,6 MiB` = `1.585,5 MiB` (margin aman `+1.310,5 MiB`). Selisih estimasi terhadap VRAM aktual Ollama (`1.531 MiB`) hanya `+55 MiB` (`3,6%`) dengan status `100% GPU` terprediksi tepat.
- **Deteksi Akurat *CPU Spillover* Model 4B:** `qwen3:4b` (`3.063 MiB`) dan `phi4-mini:latest` (`3.024 MiB`) melampaui batas VRAM pakai `2.896 MiB`, sehingga penjadwal otomatis Ollama menahan pemakaian GPU di kisaran `2.246–2.256 MiB` dan melempar sisanya ke CPU. Prediksi `%GPU` kalkulator (`69,9%` dan `71,5%`) hanya berselisih `2,0%–2,5%` dari rasio aktual `/api/ps` (`72,4%` dan `69,5%`).
- **Perbedaan `Est. VRAM` vs `Act. VRAM` & Angka Decode:** `Est. VRAM` menghitung kebutuhan jika `100%` layer dimuat penuh di GPU, sedangkan `Act. VRAM` adalah kapasitas GPU terpakai setelah sebagian bobot dipotong ke RAM akibat *spillover*. Nilai `Decode` pada tabel validasi (`4,2–18,0 t/s`) lebih rendah dibanding benchmark penuh karena hanya mengambil sampel 24 token tepat setelah *cold start* (`keep_alive = 0`).

### Kesimpulan Kelayakan Model
> Kalkulator `model_fit_calc.py` mencapai tingkat akurasi klasifikasi **`3/3 model (100% tepat)`** dengan galat rasio *offload* GPU di bawah `2,5%`, sehingga efektif digunakan sebagai *preflight check* sebelum menjalankan model baru pada perangkat ber-VRAM 4 GB.
